gwt 全画面刷新モック（PM共通版）

現行 gwt の全画面（PM画面・Issues・Works・Agents・Board・Settings・Notifications・ステータスバー）を、「端末に1人の共通PM」を前提に作り直したモックです。各画面で Before（2026-11-10 に Mac 実機 gwt v9.157.0 を巡回して実測した現行の再現）と After（刷新案）を切り替えて見比べられます。モック内の UI 文言・説明文はすべて日本語です。なお Before 側は現行製品（英語 UI）の再現ですが、内容評価を優先して、本モックでは日本語に置き換えて描いています。

網羅監査の反映（第3便）：現行 gwt の全機能と既存 Issue の決定を突き合わせた監査で見つかった抜け（大項目1件＋個別58件）を、この便で各面に戻しました。あわせて、プロジェクト単位の画面（Project 面）を新設し、Settings は4タブ化、利用量は既定表示に変更しています。既存の決定と衝突する点（#7053 AC-2 の Board のプロジェクト単位分離、#7007 FR-001／T-019 の「既存機能を失わせない」）は、該当面の説明に明記して隠していません。未決の論点は各面に「要判断」として残してあります。

オーナー決定の反映（第4便）：第3便で「要判断」として残した論点は、オーナー決定（2026-11-12）で全件決まりました——手動 Reassign はメンバー詳細に残す／コマンドパレットは入れない／Kanban は Project 面に置く／Hub は Home に統合する／実行ポリシーは見える形で出す／Issue は画面方式に寄せ窓モデルは持たない／Board は完全にプロジェクト単位にする（横断 Board 面は廃止）。各面の「要判断」表記は決定済みの表現に置き換えてあります。

モバイルの扱い：モバイルの受け口は SPEC #6476 で基盤段階にあり、モバイル最適化の本実装は #6476 側の範囲です。この #7007 モックでは全画面のモバイル版は作らず、核になる3面（Home／Decide／Ask）に電話幅（約390px）のバリアントを添えて、レイアウト方針——左レールを下部ナビに置き換える、カードは1カラム縦積み、横スクロールなし——だけを示します。

1PM は「端末に1人」

PM はプロジェクト単位ではなく端末に1人だけ置く。1人の PM が端末上の全プロジェクトを横断して受け付け・判断・報告を行う。プロジェクトを切り替えても「別の PM に代わる」のではなく、同じ PM の中で文脈が切り替わるだけ、と画面に表す。

2窓口は1つ、実行はプロジェクト別

依頼・判断・報告の窓口は1か所に集約する（横断指示を7プロジェクト分回って配る必要をなくす）。一方、実行の作業文脈はプロジェクト単位に分離したままにし、作業ツリーやプロジェクト固有の知識が混ざらないようにする。

3用語は「タスク」中心

「やりたいこと＝タスク」。概念名としての「ジョブ」は使わない（gwt 既存の語彙、および #3431 の request-task と同じ考え方）。画面の主役は常に「どのプロジェクトの、どのタスクが、今どうなっているか」。

4内部モデルを UI に出さない

Monitor / queue / worktree / operation などの内部用語、内部 ID、UTC の ISO 生文字列、略号ステータスはそのまま出さない。人向けの派生状態・相対時刻・平易な言葉に翻訳してから表示する。数値は1つの共有された状態から出すため、画面ごとに食い違わない。

数値の前提：After の各画面に現れる数値・タスク名・時刻は、すべて「2026-11-11（水）12:46 時点の、この端末の状態」という1つのスナップショットから取っています。プロジェクトは実在の7件（gwt / llmlb / event-magazine / unity-cli / 155-Demi / KeibaDB / 160-Idina）、状態は 実行中 9件・詰まり 3件・判断待ち 5件・開始待ち 18件・本日完了 12件 で全画面統一しています。現行で起きていた「タブタイトルの実行数が数分で揺れる」「面ごとに数字が食い違う」問題への回答でもあります。

プロジェクトを開く

プロジェクトを開く・取り込む・閉じる
最近開いたもの： gwt · llmlb · KeibaDB。上の行の「プロジェクトを開く」で、そのプロジェクト専用の画面（Issue・作業・エージェント・ボード・設定が1か所に集まった画面）に入ります。プロジェクトを閉じるときは、先にエージェントが終了するのを待ちます。
  • 最初に出るのは要約であって指標ではない。トークン数とコストは「今どうなっているか」の答えにならないので、Home から外した（問題1）。
  • 判断待ちは最上段の専用枠。件数つきで常に見え、Decide へ直行できる（問題5）。
  • タブタイトルも読める言葉に。「RUN 3 · BLOCK 84」ではなく「9 running · 5 need you」（問題2）。
  • プロジェクトは主役ではなく文脈。横断の要約が主で、プロジェクト別の内訳は下段に添える。
  • プロジェクトを開く入口は Home に統合した（監査 A-2／オーナー決定）。「Open project」でそのプロジェクト専用の画面（新設の Project 面）へ入り、開く／Clone／閉じるの操作もここに置く。プロジェクトを開く入口は Home に統合され、現行 Hub（/）のような独立した入口面は持たない（旧 Y-4 はこの形で決定）。下の「Open a project」節がその入口そのものである。
  • プロジェクト行に実行ポリシーの状態も出す（オーナー決定）。各プロジェクトの実効状態（ポリシー： 実行中／Waiting／Stopped）を Projects の行に添え、「どのプロジェクトが動いていて、どれが止まっているか」が Home で分かるようにする。状態の切替（Continue／Stop）自体は Project 面で行う。
  • gwt 本体の更新も Home に出す。更新が用意できたら「Update ready — restart to apply」の行を出し、適用時に稼働中の作業が安全に止められてから再起動される（drain される）旨を1行で伝える。更新ポリシー自体は Settings の App updates で変える（監査 B-1）。

このモックで決めたこと（オーナー決定）

第3便で要判断として残した論点は、2026-11-12 のオーナー決定で全件決まりました（決定 Q1〜Q7）：Q1 手動 Reassign／Switch はメンバー詳細に残す（Agents）、Q2 コマンドパレットは入れない（ステータスバー）、Q3 Kanban の置き場は Project 面（Issues／Project）、Q4 Hub は Home に統合する（Home）、Q5 実行ポリシーは見える形で出す（Progress／Project／Home）、Q6 Issue は画面方式に寄せ、窓モデルは持たない（Project）、Q7 Board は完全にプロジェクト単位にし、横断 Board 面は廃止する（Project）。いずれも該当面に決定として明記してあります。

このモックが定義するのは画面構成・情報設計・言葉づかいのみです。実装技術の選定は先行して決めません。React への移行（Issue #6943）、画面間で数字を一致させるための共有状態モデル（#5016）、Astryx 採用の可否は、いずれも別途の判断・Issue に委ねます。モック内のタスク番号・PR番号・時刻は、現行の雰囲気を保ちつつ全画面で矛盾しないよう統一した例示です。

なお本モックは、先に作成したタスク中心モック（Home / Ask / Progress / Decide / Log の Before/After）を置き換える全面版です。対象を現行 gwt の全画面（PM画面・Issues・Works・Agents・Board・Settings・Notifications・ステータスバー）に広げ、前提として「端末に1人の共通PM」を全体に通しています。
